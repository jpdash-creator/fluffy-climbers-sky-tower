# Economy module (T8): save, wallet, rewards, unlocks

Assembly `FluffyClimbers.Economy` (references Simulation, Content, Newtonsoft). Plain C# except nothing engine-specific; tested in Unity EditMode (`Assets/_Game/Tests/EditMode/EconomyTests.cs`, 28 tests).

## API
```
var repo = ContentRepository.LoadFromResources();
var svc  = new ProgressService(repo, new FileSaveStore(Path.Combine(Application.persistentDataPath, "save.json")), playableRegionLimit: 5);

svc.CanEnterRegion(region), svc.IsLevelUnlocked(level), svc.GemSkipPrice(region), svc.TrySkipToRegion(region) -> SkipResult
svc.ApplyRun(levelId, new RunOutcome { Completed, StarMask, Score, CoinsCollected, GemsCollected }) -> RewardResult
svc.Coins / Gems, AddCoins/AddGems, TrySpendCoins/TrySpendGems, TotalStars(), StarsInRegion(region), Changed event
```
Build `RunOutcome` from the finished `SimState`: `StarMask = StarEvaluator.Earned(spec, s, revivesUsed, ticks)`, `CoinsCollected = s.Coins`, `GemsCollected = s.Gems`, `Completed = GoalEvaluator.IsComplete(spec, s)`.

## Save
`SaveData` (version 1): coins, gems, per-level `LevelProgress {Stars, StarMask, BestScore, Clears}`, unlocked region ids (region 1 implicit). `FileSaveStore` writes `path.tmp`, keeps the last good file as `path.bak`, swaps, and loads in the order main, tmp, backup, fresh. Corrupt files never throw; a save from a newer app version (version greater than 1) is ignored, not guessed at. `MemorySaveStore` is for tests.

## Rules implemented (doc 01 FR-P5/P6, doc 08 section 7)
- Region 1 is always unlocked; clearing level 15 unlocks the next region if it is playable.
- Gem skip: pay `unlock.gemSkip` (500 gems for every region from 2 on since 2026-11-13, owner) to unlock the NEXT locked region without clearing the previous one.
- Teaser regions can never be entered. `playableRegionLimit` (5 for this milestone) restricts live regions in the build; content still marks regions 6-20 live.
- Coins (economy review 2026-11-13): end-of-level payout = (clear 56 + 48 per star + 4 per combo step) x region coinFactor (was 70 + 60 + 5, 20 percent cut; `CoinPayoutRules`), reduced to 25 percent (`EconomyRules.ReplayPercent`, was 50) once the level has 3 stars. The simulation still counts 5 coins per combo step (Endless pays them unchanged); a level pays `CoinPayoutRules.ComboCoins` = 4 per step. Endless and Time Attack payouts are unchanged and pay no gems.
- Gems (economy review 2026-11-13): NO gem pickups on the rows and no hidden-gem gem. Only the first clear of levels 5, 10, 15, 20, 25 pays gems, fixed 1, 1, 2, 2, 3 (9 per region, from the level JSON `rewards.gems.firstClearGuaranteed`, no chance roll; `RewardCalculator.MilestoneGemsOf`). Level 15 keeps the find-the-hidden-gem goal; the hidden gem is only the goal object and its 2 gems are that fixed reward. The old +2 level 15/25 double-gem bonus is gone. The per-run hero "Run bonus" (every completed run) is no longer paid.
- Hero milestone bonus (2026-11-13): the hero SELECTED for the run (`RunOutcome.HeroId`, empty = Common) adds on the first clear of levels 5/10/15/20/25 ONLY: Common +50 coins; Uncommon +100 coins +1 gem; Rare +200 +2; Elite +300 +3; Legendary +500 +5, and for the four upper tiers a 50 percent chance of ONE more gem (`CoinPayoutRules.HeroBonusCoins/HeroBonusGems`, roll seeded from the level seed and a fixed FNV-1a hash of the hero id, so a server can recompute it). Fixed coins, no region factor. Shown as `RewardResult.HeroBonusCoins/HeroBonusGems` (included in `TotalCoins`/`TotalGems`, so the result screen pills already count them).
- Level N unlocks when level N-1 of the same region is cleared. Best stars use the union of earned star bits; score keeps the maximum.

## Endless mode (T13, owner decision 2026-10-20)
- Save (additive, no version bump, old saves load with defaults): `endlessBest` (region id -> best floor), `endlessDay` (UTC `yyyyMMdd` the counter belongs to), `endlessRunsToday`.
- `ProgressService.ApplyEndlessRun(regionId, floors, dayKey)` records the best floor, pays the coins and saves immediately (CUX-8). The region must be enterable. No revive in endless, so the payout is final when the player falls. A run abandoned from the pause menu records nothing.
- **Coin formula** (`EndlessRewards`, doc 08 section 7): `raw = floors / 2 + 50 * (floors / 100)` (integer division), `full = round_half_up(raw x region.coinFactor)`. Examples at factor 1.0: 40 floors = 20 coins, 100 = 100, 250 = 225, 500 = 500.
- **Daily cap** (remote config `economy.endlessCoinDailyFullRateRuns` 3, `endlessCoinOverCapMultiplier` 0.5): per UTC day (`EndlessRewards.DayKey(DateTime.UtcNow)`) the first 3 paying runs pay `full`, later runs pay `round_half_up(full x 0.5)`. A run with `full == 0` (under 2 floors) does not count against the cap. The counter resets when the day key changes. The cap is global, not per region.
- Not done yet: endless gem drops at floors 250/500/1000 (once per account per day, doc 08 D2).

## Assumptions to confirm (also in `.claude/pendingdecisions/open-items.md`)
1. Star bonus is +10 percent of the payout per star beyond the first (doc 08 says "base + star bonus" without a number). Constant: `EconomyRules.StarBonusPercentPerExtraStar`.
2. A failed run pays nothing and records nothing.
3. In-run pickups no longer pay gems; on a 3-star replay the end payout is 25 percent.
4. Gem skip only unlocks the next locked region, not any region.
5. Levels inside a region unlock in order.
6. The hidden gem pays no wallet gems (the level 15 hidden gem is the goal object; its 2 gems are the milestone reward).
7. Playable region limit is code, not content: flip regions 6-20 to `teaser` in `gen_content.py` (and the validator rule) when the launch scope is final.
8. Local only: the server-authoritative wallet (PlayFab) replaces this later; the save format is the conflict-resolution unit (server wins for currencies, max wins for progress).

## Crown formula 2026-11-16 (owner, Bug List 4 items 1 and 6)
- `CrownScore.FromScore(baseScore, mode)` = baseScore x 5 x (10000 + percent x 100) / 10000, integer, half up; baseScore = `SimState.Score` = floors + sum over every chain of chain_length^2 (Sim `FloorPoints` 1, `ComboPointsMultiplier` 1). Example: floors 80, one chain of 48, Insane (50 percent) = (80 + 2304) x 5 x 1.5 = 17,880. `CrownScore.FromFloorsChains(floors, chains[] | squares, mode)` is the literal formula, `ChainSquares(int[])` sums the squares, `CrownFactor` = 5.
- This is the ONE function of every crown: level pop-up (`BestCrown`), weekly total, Endless (`EndlessBestCrown`), Time Attack (`TimeAttackBestCrown`), the (i) breakdown and the server replay (`RunReplayer`, `LeaderboardRunGlue` claim). Slots: `c.<level>.<mode>`, `e.<region>.<mode>`, `t.<region>.<mode>`.
- `CrownRun` = `{Floors f, BestCombo c, BaseScore s, Chains ch[]}` (`ch` optional: the chain lengths of the run, capped at 64, filled from `RunOutcome.Chains` / `RunRecord.Chains` when the caller sets them; the crown never depends on it). `CrownBreakdown` rows: `FloorPoints` (= floors), `ChainSquares` (= `ComboPoints`), `Chains` (list, or null when it does not match the base score), `Factor` (5), `BeforeBonus` (base x 5), `BonusPercent`, `Crown`.
- Migration: `SaveData.CrownFormula` (additive, default 0) below `CrownFormulaCurrent` (2) clears `LevelProgress.Crowns/CrownRuns/BestScore`, `EndlessCrowns` and `WeekCrowns` once on load and after `ReplaceData` (cloud restore); stars, medals, records and progress stay.
- Week = Monday 00:00 UTC (`WeekKeys`, `LeaderboardTime`, server `WeekMath`; key = that Monday's date, same yyyy-MM-dd shape). `WeekCrownData.TimeAttack` (additive) holds the Time Attack week crowns.
- Entry limits (server defaults and `config.default.json`): Overall 250,000, Regions (levels board) 100,000, Endless 150,000; ranks 1 to 3 need 1.5 x.
- **Gem levels restored (owner Main Bug List 7 item 2, 2026-11-17; supersedes the entry below).** `RewardCalculator.Compute` sets `RewardGems = GemLevels.FixedFirstClearGems(level.Index)` (levels 5/10/15/20/25 = 1/2/2/3/4, first clear only, no pickup needed). `MilestoneGemsOf(level)` returns that fixed number (tile badge `MetaController.AddGemBadge` and level pop-up show it on every milestone level). `GemsInLevel(level)` is the COLLECTIBLE count (0, 2 or 3; extra to the fixed gems); `PickupGems` is clamped to it (anti-tamper) and 0 on a reduced replay. Hero bonus unchanged.
- **Collectible gems replace the milestone gems (owner Bug List 4, 2026-11-16).** `RewardCalculator.MilestoneGemsOf(level)` (name kept for the level tiles and pop-up) now returns the gems the level HOLDS = `GemLevels.GemsInLevel(level.Index, level.Seed)` (0 or 2 on levels 5/10/15/20 by the seeded 50 percent roll, 4 on level 25, `RewardCalculator.GemsInLevel` is the same). `RewardResult.PickupGems` = the gems the completed run collected (`RunOutcome.GemsCollected`), 0 when the level holds none or on a reduced replay; `RewardGems` and `HiddenGemReward` are always 0; the hero milestone bonus (`HeroBonusCoins/Gems`) is unchanged. The level JSON carries no `firstClearGuaranteed` any more. The tile badge should show when the level holds gems and the player has not collected them yet.

## Purchase ledger and Reset progress (owner 2026-11-17, Bug List 5 item 5)
- Reset progress wipes everything saved (levels, stars, medals, crowns, records, goals, ALL rewards, earned coins/gems/heroes/power-ups, regions, leaderboard queue and caches) EXCEPT what shops and real money granted. Code: `ProgressService.Ledger.cs` (`ResetAll()`, `ResetAll(nowUtc)`, `ApplyLedger`, `ClampLedger`), data `PurchaseLedger.cs` (`SaveData.Ledger`, JSON `ledger`, additive).
- Ledger = "still owned from purchases": `Coins`, `Gems`, `Powerups` (id to units), `Heroes` (id to `{n copies, rolls[], rollNos[]}`, one roll per bought copy; `roll`/`rollNo` mirror the first). Written in the SAME save as the grant: `TryBuyCoinPack` (coins), `TryBuyPowerUp`, `TryBuyHero`, `BuyBundleCore` (coins, power-ups, hidden card), `TryOpenChests` (a gem-bought chest is a shop purchase: its whole content counts, however the gems were earned), `CreditGemPack` and `CreditSubscription` (instant gems) only while `GrantWithRecord` runs a real purchase (admin/test credits are not recorded). Hero copies go through `AddBoughtCopy` -> `AddCopiesCore` (deals each new copy its own roll, records it).
- NOT recorded: level payouts, rewards, daily claims and chests of a subscription, weekly prizes, region skips, `GrantPowerUp`/`AddCoins`/`AddGems`/`AddCopies`.
- Every `Commit()` clamps the ledger to the wallet, the power-up stock and the hero copies (spent, used or merged-away items leave it; spent earned currency counts first, the player-friendly side). A merge of 3 bought copies makes the merged hero bought too (`LedgerOnMerge`; the ledger entries that leave are the merged cards' rolls).
- Rebuild: wallet = ledger coins/gems, stock = ledger power-ups, `Copies` = starter copy (Momo) + ledger copies, `HeroCopyRolls/HeroCopyRollNos/HeroRollCount` from the ledger (every copy gets its own rolled stats back). Subscription = `RestoreFromRecords` over the kept `Purchases` (period only, instant gems come from the ledger, daily claims start fresh). Kept: login/account, `Purchases`, `FirstPurchase`, leaderboard consent, name and granted claim ids.
- Purchases made before v0.62 (before the ledger existed) cannot be told apart and count as earned: the confirm text says so (`MetaController.ResetMessage`).
- Cloud: the ledger is part of `SaveData`, so the existing cloud save (Play Games Saved Games, `SaveSync` envelope) carries it; reinstall + sign-in restores purchases with the rest. `SaveData.CloudResetPending` (set by a reset while a Google account is linked, cleared by `MarkCloudSynced`) makes `AccountSync.Resolve` upload the device save instead of applying an older cloud save, so a failed upload can never undo a reset.
- Leaderboard: `SaveData.LeaderboardWipePending` (set when the player ever consented) makes `LeaderboardHub` call `POST /delete-my-entries` (`LeaderboardClient.DeleteMyEntries`) at reset, at the next sign-in and on every slow tick until it succeeds; `Pump` uploads nothing while it is pending.
- Follow-ups (server authority): the ledger is client data like the whole save. Guests (no cloud save) lose purchases on uninstall; gem packs are consumables that Play Billing never re-delivers. A server-side validated purchase ledger (receipt validation, docs/13) is needed to restore those for guests and to make currencies server-decided.

- Crown calculation sync (owner 2026-11-17): `CrownRun.At` (UTC seconds, monotonic per week store) stamps every weekly slot version; `BreakdownMerge.cs` (shared with the leaderboard service) holds the merge rules, `ProgressService.Breakdown.cs` the phone side (`LocalBreakdown`, `MergeCloudBreakdown`, `BreakdownRevision`). `WeekSlotInfo` gained score, combo, chains, at, ra, verified (all additive).
